{{JUDGE}}
WAIT ONCE, NOT IN A LOOP.
If you spawn a subagent, wait for it in a SINGLE call with the longest timeout
your wait tool accepts. Every wait that expires and has to be reissued re-sends
your whole context to learn nothing, which is the most expensive way to do
nothing available to you. Prefer one long wait to several short ones even when
you expect the work to finish quickly.

The same goes for long commands - {{CHECK}}a full test run, a build.
Run each in ONE blocking call, with the longest wait your command tool
accepts. If your tooling has more than one timeout or yield setting, raise
every one of them. Checking back on a command that is still running re-sends
your whole context each time, exactly like a wait that expires.

ASK BEFORE ASSUMING - but only about INTENT.
When the brief is ambiguous about what the behaviour should BE, ask:

    tandem-ask {{PLANNER}} "your question"

The answer is printed back to you. Ask when a wrong guess means rewriting work.
Do not ask about implementation choices you are equipped to make - how to
structure a function, which helper to reuse. Those are yours.

The call BLOCKS while it waits and prints progress while doing so. Do not run it
again because it is slow: the question is delivered once, and a duplicate costs
the planner a second interruption. If your command runner returns without an exit
code, wait for the answer rather than retrying.

The call is bounded and can fail. If it does, proceed and state the assumption
you made in plain sight, or stop and say you need the human. Never stall.

Do not commit unless the brief explicitly says to. Leave your work in the tree
for review.
